# Yantra on Android

**Status: the APK builds from this repo's own sources on this box, with the same
engine, the same sandboxed WebAssembly apps and the same `env.y_*` import table
as the desktop — and the app modules inside it are byte-identical to the
desktop's.**

This document is the plan *and* the receipt: every fact below was measured on
this machine on 2026-11-06 and carries the command or report that produced it.
The per-component reports with the full transcripts live in
`android/third_party/reports/` (gitignored, regenerated by the recipes here).

## 3. The APK

Built by one command:

```bash
bash tools/build-android.sh           # from anywhere; paths derive from the script
```

It checks the toolchain, checks/creates the `third_party` symlink farm the
desktop wrappers expect, compiles the host, compiles + dexes the Java, copies the
app modules into `assets/apps/`, packages with `aapt2`, aligns, signs, verifies,
and prints the interchangeability table (below). Dependencies are looked up under
`android/third_party` and produced by the recipes in their reports.

## 4. Interchangeability — the point of the port

**The claim:** an app module is platform-neutral. It imports only `env.y_*` (plus
`env.nim_write`, `env.nim_exit`, the `vajra_*`/`sutra_*` vocabulary functions and
the C math functions the Nim WASI target emits). The desktop host defines that
table; the Android host defines the *same* table because it is literally the same
`host/host.nim`. A module that runs on one and not the other is a **bug in the
host**, never a reason to rebuild the app.

`tools/build-android.sh` proves it on every build: it unzips each
`assets/apps/<id>/app.wasm` out of the finished APK and compares its sha256 with
`yantra-os/apps/<id>/app.wasm`, failing the build on any difference.

## 5. Parity: "just as powerful" as a table, not an adjective

Desktop capabilities vs what the Android host actually does today. "Linked" means
the real library is compiled in and the import is wired; "verified" means a run
proved it (see §6).

| capability | desktop | Android today | what it takes to close |
|---|---|---|---|
| **Drawing** (rounded rects, gradients, shadows, paths, layers, effects) | Skia chrome/m143, CPU raster into a pixel buffer | **same Skia, same shim, same code path** — `paintFrame()` → CPU buffer → SDL texture | — |
| **Text** (paragraphs, styles, runs, RTL, inline images, selection) | Skia SkParagraph + SkShaper + ICU + FreeType | **same**, with a platform font fix: `skia_shim.cpp`'s `__linux__` branch looks for `/usr/share/fonts`, which a phone lacks → prelude points Skia's real directory font manager at `/system/fonts` (see §7) | verify CJK/emoji fallback on a device; ship a font override via `YANTRA_FONTS` if a family is missing |
| **Input** (pointer, wheel, hover, keys, text, gamepad) | mouse/keyboard | **touch works** (SDL synthesises mouse events from touches), on-screen keyboard types into focused text fields, Back is an SDL key event; gamepad + haptics through SDL's Java glue | hover/right-click/wheel have no fingers: add a long-press → context menu mapping in `MainActivity` (small) |
| **Presentation** | `SDL_Renderer` + streaming texture, vsync | **identical** (`ys_present`), 1 texture upload per frame | — |
| **Sound** | miniaudio | **linked** (miniaudio cross-built with the AAudio/OpenSL backend) | needs a device test: the JVM/AAudio stream cannot start without audio hardware |
| **3D** (Filament) | Filament v1.77.1 + Ganesh GL | **linked, real Filament v1.77.1** (same version, proven by `MATERIAL_VERSION = 77` on both), 37/37 `yf_*` symbols, headless `createSwapChain` + `readPixels` by design. | **Files** (`y_file_read`, app dirs) | real filesystem | **same** — apps live under the app's private `filesDir` after a one-time byte copy; `resolveAsset` works on those paths | system file picker (`ys_show_open_file`) has no Android implementation in SDL → `y_pick_open` is a stub today; fix = `ACTION_OPEN_DOCUMENT` in Java + JNI callback |

## 6. Running it

### On the owner's phone (3 lines)

```bash
adb install -r yantra-os/bin/yantra.apk
adb shell am start -n com.svarogsystems.yantra/.MainActivity
adb logcat -s YantraHost          # the engine's own proof lines
```

(Without adb: copy the APK to the phone, tap it, allow "install unknown apps".)

Watch for these logcat lines — they are the host saying, in its own words, that
it booted, found the module, opened a window and painted:

```
YantraHost: assets copied: 41 files -> /data/user/0/com.svarogsystems.yantra/files/apps
YantraHost: engine boot: app=desktop module=/data/…/files/apps/desktop/app.wasm bytes=1258658
YantraHost: window 1080x2400 density=2.75
YantraHost: frame #1 1080x2400 (t=   183ms)
```

`am start … -e app calc` boots a different app from the same APK.

### On this box — and exactly what is missing

Two measured facts decide this:

1. **`/dev/kvm` does not exist here** (`ls -l /dev/kvm` → No such file).
2. **The Android emulator on an x86_64 host cannot run an arm64-v8a image**, KVM or
   not: installing `system-images;android-34;google_apis;arm64-v8a` (done) and
   starting it prints
   `FATAL | Avd's CPU Architecture 'arm64' is not supported by the QEMU2 emulator
   on x86_64 host. System image must match the host architecture.`
   so an x86_64 AVD cannot load our arm64 `.so`s, and the arm64 AVD cannot start.

The fallback tried was `qemu-aarch64-static` with a **statically linked** build of the
same host (`-static -fno-emulated-tls`, one 64-byte-aligned TLS object, SDL3 static):
the binary links and is a valid `ARM aarch64` static executable (160,520,840 B), but
bionic's *static* libc crashes in `sigaction()` before `main` (`qemu: uncaught target
signal 11`; gdb-multiarch backtrace: `#0 sigaction … bionic/libc/bionic/sigaction.cpp:63`,
frame #1 corrupt). A trivial Nim-for-Android static binary does run under
`qemu-aarch64-static` (`hello from nim+android+qemu`), so the toolchain is fine and the
failure is in the static-bionic + wasmtime trap-handler path — **not** in the APK,
whose `libmain.so` is a normal bionic shared object. The definitive run is the phone.

Each component library *was* separately executed on this box under
`qemu-aarch64-static`: SDL3 reported `3.2.16` / `release-3.2.16-0-gc9a6709bd`;
wasmtime printed `add(2,3)=5`; Skia drew a rounded rect + the string "Yantra"
(`yk_text_measure` → 65.980 × 23.000 with a font, checksum changing by 4096 px);
FFmpeg's shim wrote a real 13,551 B `.m4a`. See `android/third_party/reports/*.md`.

## 7. What had to change, and what did not

**Did not change:** `render/native/engine.nim`, `host/host.nim`, `host/tree.nim`,
`protocol/wire.nim`, any `libs/nim*/src/*` wrapper, any app, any app module. The
engine compiles for `--os:android` unmodified (Nim's android target also defines
`linux`, so the wrappers' Linux branches are the ones taken).

**Did change — all of it inside `android/`, plus three gitignored conveniences:**

| seam | why | how |
|---|---|---|
| `third_party -> android/third_party` (symlink) | the wrappers compute `<repo>/third_party/<lib>` at compile time | created by the build script; gitignored, so it never enters a commit |
| `yantra-os/libs/nimwasmtime/vendor/wasmtime-v19.0.2-linux-c-api/` | `raw.nim` finds wasmtime by scanning for a `*‑linux-c-api` **real directory** (`walkDir` skips symlinked dirs) | real dir whose `include/` and `lib/` are symlinks |
| `libs/nimyoga/build/libyoga.a`, `yantra-os/libs/nimminiaudio/build/libminiaudio.a` | the wrappers hardcode those build paths | the Android archives are installed there (both dirs are gitignored) |
| `android/src/androidlibs/nimjolt.nim` | the desktop wrapper compiles its shim with `-mavx2 -mfma`; clang rejects those for arm64 (`error: unsupported option '-mavx2'`) | the same Jolt C API declared with arm64 flags; put last on Nim's search path (Nim searches `--path` in reverse, measured) |
| `android/src/skia_android_fonts.h` | `skia_shim.cpp`'s `__linux__` branch takes fonts from `/usr/share/fonts` — absent on a phone, so every text width would be 0 | a `-include` prelude that keeps Skia's real directory font manager and points it at `$YANTRA_FONTS`, else `/system/fonts` |
| `android/src/skia_gl_stubs.cpp` | `skia_shim.cpp`'s GPU block is guarded by `#ifndef __EMSCRIPTEN__`, so it compiles on Android although our Skia is CPU-raster | three null-returning Ganesh-GL factories; `yk_gpu_new()` already treats null as "no GPU" |
| `android/third_party/stublib/{libGL.a,libpthread.a}` + a linker wrapper | `nimskia` passes `-lEGL -lGL`, `nimav`/`nimskia` pass `-lpthread`; the NDK has no `libGL.so` and no `libpthread.so` (bionic folds pthread into libc) | empty archives (nothing references GL; pthread symbols live in libc) put on the link line by a one-line linker wrapper |
| API level **28**, not 24 | NDK declares `glob()` only for `__ANDROID_API__ >= 28`, and `host.nim` uses `glob` | `API=28` in the build script, `minSdkVersion 28` in the manifest |

## 8. Honest gaps (what is *not* proven yet)

1. **No on-device run yet — measured, not hand-waved.** §6 states it exactly: no
   `/dev/kvm`; the emulator refuses arm64-v8a on an x86_64 host; the static-bionic
   qemu harness dies in `sigaction`. The APK itself is built, signed, verified, and
   every library in it was separately executed under qemu on this box.
2. **`y_pick_open` / `y_pick_save`** have no Android implementation in SDL → stub.
3. **`y_call`** uses the desktop's own `rtc_stub.c` (calls never start).
4. **Hot reload** and the **MCP port** are desktop-only conveniences today (§5).

## 8.1 Reproducibility of the APK

`tools/build-android.sh` pins every input it can: the deps are archives on disk
(their sizes and sha256 are in `android/third_party/reports/`), the zip stage
normalises every mtime to `SOURCE_DATE_EPOCH` (default 1700000000) and uses
`zip -X`, and `zipalign`/`apksigner` run in a fixed order. Re-running the script
on unchanged inputs therefore produces the same entries in the same order; the
signature bytes can differ only if the keystore is regenerated (the script keeps
`android/app/build/yantra-debug.keystore` once created).

## 9. Risks

1. **No hardware acceleration on this box** → a first-run proof comes from an
   emulator under TCG or from qemu-user, i.e. it is slow and partial; the
   definitive check is the owner's phone.
2. **Three seams are load-bearing and outside the tracked wrappers** (`-mavx2`,
   `/usr/share/fonts`, `glob`). They are documented and mechanical, but the real
   fix is a `when defined(android)` branch in `libs/nimjolt`, `libs/nimskia` and
   SDL-side `glob` handling — one small commit each, for whoever may edit `libs/`.
3. **APK size.** Skia+ICU, wasmtime and Filament static links make `libmain.so`
   tens of megabytes. Play Store/phone installs are fine, but a smaller slice
   (drop ICU, use `-d:useMalloc`, split per-ABI) is future work.
